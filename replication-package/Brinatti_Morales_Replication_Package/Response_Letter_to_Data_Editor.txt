--------------------------------------------------------------------------------
1. MISSING MATLAB TOOLBOX (Report Summary, item 1; Section 8 "Replication")
--------------------------------------------------------------------------------

Your team's run failed on mvnrnd in Heterogeneity.m (called from
Counterfactual_heterogeneous_open.m / Counterfactual_heterogeneous_closed.m)
until the Statistics and Machine Learning Toolbox was installed, even though
our README stated that no additional MATLAB toolboxes were required. README
Section 3.2 now lists the Statistics and Machine Learning Toolbox as a
requirement alongside the Optimization Toolbox, with the specific function
(mvnrnd) and file that need it named explicitly.

--------------------------------------------------------------------------------
2. WHERE TO PUT THE ADO FILES (Report Summary, item 2)
--------------------------------------------------------------------------------

README Section 3.1 previously named the three non-SSC ado files
(bartik_weight.ado, btsls.ado, ch_weak.ado) and their source but did not say
where to place them. It now explains that they should be copied into
liab_analysis/prog/ (already on the adopath via `capture adopath++ ${prog}`
in every liab_analysis do-file that needs them), or alternatively into the
user's personal Stata ado directory (via `sysdir`).

--------------------------------------------------------------------------------
3. CODE TO GENERATE THE FIGURES (Report Summary, item 3; Section 9.3, "No
   image files produced by code; only underlying data tables")
--------------------------------------------------------------------------------

Because of FDZ output-disclosure rules, the figures in the empirical folders
were historically produced as underlying data tables only, which we then
turned into figures by hand in Excel; the code itself never produced an
image file. We have added a Stata plotting section to the end of every
do-file that was flagged as missing this, in every case reading back the
already-disclosed tables/estimates without altering any of the existing
analysis code:

  liab_analysis/prog/17_empirical_facts.do
      Figures 1, A1(a)-(d), A2(a)-(b), A3, A4(a)-(b), A6(a)-(b)
      (12 panels total; Figure A3 is rendered as a bar chart, matching the
      paper, all others as connected-line plots with 95% CI whiskers)
  liab_analysis/prog/18_immigrant_comparative_advantage.do
      Figure A9
  sieed_analysis/prog/2a_results_event_studies.do
      Figures 2 and A8 (the coefficients were only ever printed via esttab/
      lincom; we now capture them via `estimates restore` on the models
      already stored by the existing eststo calls, with no re-estimation)
  sieed_analysis/prog/2b_results_figA7.do
      Figure A7 (point estimates and bootstrap SDs were only ever printed
      via `table`; both are now also stashed to small datasets and merged)
  sieed_analysis/prog/2c_results_figA5.do
      Figure A5 (2 panels; same `table`-only limitation as above)

Each added section is clearly marked with a header comment beginning
"FIGURE(S) (added for JPE reproducibility deposit -- not part of the
original submission)" and states explicitly that it does not modify any of
the pre-existing analysis. Output is written to a new output/ subfolder
created inside liab_analysis/ and sieed_analysis/ respectively (e.g.
liab_analysis/output/figure_1.jpg). Figures 3, 4, D1 and D2 in
model_analysis already produced .jpg files via existing code and required
no changes.

Because the published figures were built by hand in Excel from these
disclosed tables (styling, colors, and markers chosen by the authors), the
newly added Stata graphs reproduce the same underlying numbers but are not
pixel-identical to the published versions. We have added a "NOTE ON EXACT
APPEARANCE" to the header of every added plotting section, and a
corresponding note in README Sections 4.2, 4.4 and 6, making this explicit.

7. POTENTIAL PII INDICATORS (Report Sections 7.1 and 10.2)
--------------------------------------------------------------------------------

We reviewed the flagged variable names and file contents (e.g. "son",
"lat", "loc", "url", "sex", "name", "country"). To the best of our
knowledge these are false positives from substring matching within longer
variable or field names (e.g. "person", "season", "local", "location")
rather than actual personally identifying information. README Section 2.4
now includes a note to this effect, and states more generally that the
confidential IAB/FDZ data are anonymized by the data provider before being
made available to researchers, that all analysis and disclosure followed
the FDZ's own statistical disclosure control process (Section 2.5), and
that this project was reviewed by the University of Michigan Institutional
Review Board and determined to be exempt from IRB review.
