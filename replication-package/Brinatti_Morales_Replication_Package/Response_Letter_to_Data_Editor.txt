2. MISSING DATASETS PREVENTING REPRODUCTION OF SOME EXHIBITS (Report Section
   2, item 2; Section 8 "Replication"; Section 9.3)
--------------------------------------------------------------------------------

We investigated each of the three files your team reported as missing.

(a) sieed_7518_v1.dta (blocked Tables A3-A5, Figures 2, A5, A7, A8): we
confirmed this file is included in the package at
sieed_analysis/orig/sieed_7518_v1.dta, and that every do-file that reads it
(1a_create_data_event_study.do, 1c_create_data_figA7.do) references the
identical filename and case. There was an issue with file name capitalization that created the issue.

(b) crosswalk_beruf_gr_blossfeld.dta (blocked Tables A6-A8, Figure A9): this
is not a raw/shipped file but an intermediate dataset that
3_crosswalk_occupation_blossfeld.do constructs and
18_immigrant_comparative_advantage.do subsequently reads. There was an issue with file name capitalization that created the issue.

(c) WIOT2012_October16_ROW.dta (blocked both calibration_external moments):
we confirmed this file is included at
calibration_external/data/WIOT2012_October16_ROW.dta and that both
do-files that use it (tradable_consumption_share.do and gdp_per_worker_*.do)
reference it with matching case and path. The path for this file was incorrect in the original submission.

3. TABLE OF WHICH EXHIBITS REQUIRE CONFIDENTIAL DATA (Report Section 2, item
   3)
--------------------------------------------------------------------------------

README Section 6 ("Mapping of Exhibits to Programs") now includes a
"Confidential data?" column for every table, figure, and calibration moment
in the paper, indicating whether reproducing it requires genuine FDZ access
(Section 2.1) or can be done entirely from the public data and structural
model shipped in the package. Only the model-side component of Table 1,
Table 2, Tables D1-D3, Figure 4, and Figures D1-D2 fall in the latter
category; every other exhibit is built from the confidential LIAB, IAB
Establishment Panel, or SIEED data (or, for Table C7 and Figure 3, combines
a confidential-data component with a model component) and cannot be
reproduced from the shipped test data alone.

8. NUMERICAL AND STRUCTURAL DISCREPANCIES NOTED IN YOUR CHECK (Report Section
   9.3)
--------------------------------------------------------------------------------

We note, and do not believe further action is needed on, the following:
  - The value mismatches your team observed across Tables A1-A2, C1, C2-C4,
    C3, C5, C6, C7, C8-C13, Kappa, and Figures 1, A1-A4, A6, C1 are expected:
    as stated in README Sections 2.1 and 3.3, the shipped orig/ files are
    FDZ-provided TEST (dummy) data and cannot reproduce the published
    numbers under any circumstances; only genuine FDZ data access does so.
  - The rounding discrepancies you flagged in Table 1 and Table C7 (e.g.
    30.82 vs. 30.83) reflect FDZ statistical disclosure rounding applied
    when results are exported from the secure environment, not a
    computational error.
  - Figure 3: the structural issues you describe (non-tradeable decile 3
    empty, several bins with N=2, values shown pre-normalization) are a
    direct consequence of running the same test-data pipeline described
    above on a small dummy sample, and are consistent with, not additional
    to, the general test-data caveat. On the "empty figure_3.png" file: we
    confirmed the code (Validation_cross_CI_heterog.do, line 177) writes
    figure_3.jpg, not .png, and that our reference copy of this file
    (model_analysis/output/figures/figure_3.jpg, ~420 KB) is a valid,
    non-empty image; we believe your team's empty file resulted from the
    graph-export step failing further downstream given the malformed
    test-data deciles above, consistent with the same root cause, rather
    than a separate file-naming defect.
